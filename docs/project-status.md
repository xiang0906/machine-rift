# Machine Rift 專案現況

> 更新日期：2026-08-06
> 階段：可遊玩的全端 MVP

## 1. 專案定位

Machine Rift 是一款以瀏覽器 Canvas 呈現的塔防遊戲。Spring Boot 後端負責帳號、
玩家進度、關卡內容、對戰紀錄與排行榜；MySQL 保存正式資料，Flyway 管理資料庫版本。

目前 MVP 已形成完整循環：

1. 玩家建立帳號或登入。
2. 系統載入該玩家的關卡、塔解鎖與最佳戰績，並進入遊戲大廳。
3. 玩家從大廳選擇任務、工坊或戰績中心；選擇已解鎖關卡後進行塔防遊戲。
4. 結束後將勝敗、分數與遊玩時間寫入後端。
5. 後端更新金幣、個人最佳與解鎖內容。
6. 玩家可返回大廳查看個人歷史戰績與排行榜。

## 3. 系統分層

```text
Browser / Canvas UI
        │ REST + Bearer token
        ▼
Controller
        ▼
Service（驗證、進度、解鎖與戰績規則）
        ▼
Repository
        ▼
JPA Entity
        ▼
MySQL / H2
```

後端套件責任：

| 套件 | 責任 |
| --- | --- |
| `controller` | REST API 與 HTTP 狀態 |
| `service` | 帳號、進度、解鎖與戰績規則 |
| `repository` | Spring Data JPA 查詢 |
| `entity` | 資料表映射與關聯 |
| `dto` | API 請求與回應契約 |
| `mapper` | Entity 與 DTO 轉換 |
| `exception` | 統一例外與錯誤回應 |
| `config` | 密碼編碼器等共用設定 |

## 4. 帳號與權限

- 玩家以唯一帳號和密碼登入。
- 玩家顯示名稱不分大小寫且不可重複。
- 帳號長度為 3～50 個字元，可使用特殊符號，但不可包含空白或控制字元。
- 密碼長度為 8～72 個字元，資料庫只保存 BCrypt 雜湊。
- 登入後產生 30 天有效的 Session；Token 的 SHA-256 雜湊保存在 `player`。
- 每位玩家只保留一個有效 Session，重新登入會取代前一個登入狀態。
- 登出會撤銷目前 Session。
- 玩家進度、戰績寫入與排行榜需要 Bearer Token。
- 玩家不可讀寫其他玩家的私人進度或代替其他玩家寫入戰績。

## 5. 玩家進度

每位玩家保存：

- 永久戰備金與完成關卡數
- 每關是否解鎖
- 每關完成次數
- 每關最高分與同分時的最短完成時間
- 已解鎖防禦塔

目前解鎖規則：

- 新玩家取得第一個可遊玩關卡與最便宜的塔。
- 首次完成關卡會增加完成關卡數並解鎖下一關。
- 勝利會依關卡設定增加永久戰備金，但不再自動解鎖防禦塔。
- 玩家可自由選擇尚未解鎖的塔，由後端確認戰備金後永久購買。
- 勝利時依關卡設定增加金幣。

## 7. 資料庫

專案共有 9 張業務資料表，另有 Flyway 的 `flyway_schema_history`：

| 資料表 | 責任 |
| --- | --- |
| `player` | 帳號、密碼、總進度與目前登入 Session |
| `player_stage_progress` | 關卡解鎖、完成次數與個人最佳 |
| `player_tower_unlock` | 玩家實際解鎖的防禦塔與解鎖時間 |
| `stage` | 關卡基本資料 |
| `stage_path` | 關卡路徑節點與順序 |
| `stage_wave` | 波次、敵人、數量與生成間隔 |
| `tower` | 塔的類型、傷害、攻速、射程、戰場造價與永久解鎖價格 |
| `enemy` | 敵人生命、速度與擊殺獎勵 |
| `game_record` | 每場遊戲的分數、勝敗、遊玩時間與建立日期 |

V14 將 `player_progress`、`player_session`、`player_tower_unlock` 合併至 `player`。
塔依造價順序解鎖，因此只保存解鎖數量即可還原玩家目前可使用的塔；每關解鎖與個人最佳
仍由 `player_stage_progress` 保存。
V15 在 `game_record` 加入 `created_at`，既有戰績會在 migration 時補上時間，後續戰績則
在建立時自動記錄日期。
V16 恢復 `player_tower_unlock`，依 V14 保存的數量與塔造價順序搬回既有解鎖紀錄，
再移除 `player.unlocked_tower_count`。
V17 為 `tower` 加入 `unlock_cost`，將永久解鎖價格與單局建造造價分開。購買時會鎖定
玩家資料，並在同一個 transaction 內檢查重複解鎖、確認永久戰備金、扣款及建立解鎖紀錄。
V18 保留第 1 關教學強度，逐步提高第 2～6 關敵人數量；第 4～6 關同步縮短生成間隔，
並把全域高階敵人「裂隙核心、裂隙巨像」的基礎生命提高 10%。
V19 移除未參與關卡、塔、獎勵或排行榜邏輯的 `player.level` 與 `player.experience`，
玩家進度改由永久戰備金、完成關卡、塔解鎖與戰績直接呈現。
V20 將後期耐久型敵人的移動速度小幅提高：護盾機兵 40、裂隙核心 38、裂隙巨像 29；
前三種前期敵人的速度維持不變，避免影響教學關卡節奏。
V21 再將疾風無人機以外的五種敵人跑速各提高 10，目前依序為偵察機 72、裝甲機 55、
護盾機兵 50、裂隙核心 48、裂隙巨像 39；疾風無人機維持 92。

## 8. API 現況

| 範圍 | 端點 |
| --- | --- |
| 帳號 | `POST /api/auth/register`、`POST /api/auth/login` |
| Session | `GET /api/auth/me`、`POST /api/auth/logout` |
| 私人進度 | `GET /api/players/me/progress` |
| 關卡 | `GET /api/stages` |
| 防禦塔 | `GET /api/towers`、`POST /api/towers/{towerId}/unlock` |
| 戰績 | `POST /api/game-records`、`GET /api/game-records/me` |
| 排行榜 | `GET /api/rankings`、`GET /api/rankings?stageId={id}` |

目前共 11 支核心 API。未使用的公開玩家清單、玩家維護、關卡／防禦塔後台 CRUD、
單筆查詢與公開戰績查詢端點及其輔助程式已移除。防禦塔購買 API 已完成交易規則，
並由遊戲大廳中的防禦塔工坊串接。個人歷史端點只回傳 Token 所屬玩家最近 20 場戰績，
依建立日期由新到舊排列。
排行榜可查詢全部關卡或指定關卡，由後端選出每位玩家在該範圍的最佳戰績，依分數降冪、
時間升冪排列，最多回傳前十名，並直接包含排名、玩家名稱、關卡名稱、分數、時間、結果及統計。
私人進度與戰績寫入的玩家身分完全由 Bearer Token 決定；進度網址與戰績 request
都不再接收 `playerId`。
所有回應使用統一的 `ApiResponse` 格式，完整 API 可在 `/swagger-ui.html` 查看。
Controller 成功訊息、DTO 驗證訊息及 Service 業務錯誤皆統一使用中文，前端可直接顯示。

## 9. 前端現況

- 前端已拆分為 HTML 結構、共用 CSS、核心狀態、畫面控制與 Canvas 遊戲引擎。
- `index.html` 只保留七個畫面的 HTML 結構及靜態資源載入。
- `core.js` 負責 API、Session 與玩家內容；`views.js` 負責畫面；`game.js` 負責塔防引擎；
  `story.js` 保存輕量敘事文案。
- 七個畫面使用 `#/login`、`#/register`、`#/lobby`、`#/towers`、`#/stages`、`#/records`、`#/game` hash 路由，
  網址會隨畫面更新並支援瀏覽器上一頁／下一頁；舊的 `#/history`、`#/ranking` 會導向戰績中心。
- 大廳、關卡、戰績中心與遊戲路由需要登入；直接開啟 `#/game` 或在戰鬥中重新整理時，因本局
  狀態只存在記憶體，登入恢復後會安全返回遊戲大廳。
- 首頁為登入畫面，首次遊玩的玩家可切換至建立帳號。
- 登入或恢復 Session 後先進入遊戲大廳；大廳顯示永久戰備金、完成關卡與解鎖塔數，
  並提供防禦塔工坊、任務、戰績中心與登出入口。
- 全站採用科幻戰術藍圖視覺：深藍網格、青灰細線與霧面卡片，顏色依任務／資源／安全／
  危險語意使用；戰場另有淡色地形分區及低亮度間歇掃描效果。
- 大廳採裂隙作戰指揮中心風格，加入雷達主視覺、指揮官識別卡、雙進度條及系統建議行動；
  三個功能入口以任務、軍械庫與作戰資料的獨立色彩呈現，不新增後端功能。
- 觸控手機以直式進入戰場時會顯示橫向模式提示；旋轉後自動部署，也可維持直式進入或
  返回任務簡報。桌面與手機橫向不會顯示提示。
- 工坊、關卡選擇與戰績中心使用一致的分類標籤、中文標題、用途說明與頁首返回按鈕；
  手機版返回按鈕會置於標題文字下方，避免長頁面需要捲到底部才能離開。
- 防禦塔工坊顯示全部塔種、戰鬥數值、戰場造價與永久解鎖價格；玩家可用永久戰備金自由購買，
  已解鎖與金幣不足的塔會停用購買，成功後立即刷新玩家金幣、解鎖數與遊戲塔庫。
- 首頁包含三行世界觀；六個關卡各有任務說明、進場簡報及勝敗結果文字。
- 關卡選擇頁以兩欄緊湊卡片呈現，操作教學預設收合；遊戲內也會顯示精簡操作提示。
- Access Token 保存於瀏覽器，重新開啟時透過 `/api/auth/me` 恢復登入。
- 關卡頁顯示全部六關、鎖定狀態與個人最佳成績。
- 關卡頁只保留關卡選擇、操作教學與返回大廳，避免次要功能擠在同一頁。
- 大廳提供戰績中心入口，以頁籤整合個人歷史與榮耀排行榜；個人歷史依日期顯示最近
  20 場的關卡、勝敗、分數與遊戲時間。
- 榮耀排行榜可從下拉選單切換全部關卡或六個個別關卡，不增加新的頁面或 API 數量。
- 遊戲畫面使用左側固定 Canvas 與右側可捲動塔庫。
- 選塔後會預覽建造格、合法狀態及攻擊範圍；金幣足夠時可連續建造同一座塔，
  不足以再建造時會自動取消選取。
- 戰場頁首優先顯示任務名稱與目前波次；HUD 統一呈現作戰時間、生成進度、基地耐久與分數。
- 波次切換使用一次性短動畫，低血量使用持續警示；建造與操作訊息依重要程度區分樣式。
- 可用金幣顯示於右側塔庫，方便與防禦塔造價比較。
- 放棄本局前會顯示確認訊息，避免誤觸後直接離開。
- 塔庫標示目前選取塔種，金幣不足的塔會降低亮度。
- Canvas 提供命中閃白、擊殺金幣浮字、基地震動、低血量警示與勝利前短暫停頓。
- 窄螢幕時塔庫改成橫向滑動，避免塔卡將遊戲畫面推離視窗。
- 塔可依造價或傷害升冪／降冪排序，偏好依玩家保存在瀏覽器。
- 不同塔使用不同顏色；不同敵人使用不同顏色與體型。
- 排行榜只能登入後查看，顯示前三名頒獎台與前十名。

## 11. 已知限制

- 前端已完成實體檔案拆分，但 JavaScript 仍採依序載入的原生腳本；若功能繼續增加，
  可再導入 ES Modules 與明確的匯入／匯出介面。
- 目前沒有完整的 Spring Security Filter Chain，權限由 Controller 呼叫 `AuthService` 驗證。
- 敵人只有生命、速度與獎勵，尚未支援護甲、緩速抗性或特殊技能。
- 防禦塔只有基本單體攻擊，尚未支援升級、範圍傷害、緩速或減益。
- 沒有密碼重設、電子郵件驗證、限流與登入失敗鎖定。
- 排行榜已在後端彙整，但 MVP 仍會讀取全部戰績；資料量明顯增加後才需要資料庫分頁。
